# Laboratorios de ingeniería inversa de MAGSTV

Tooling for the MAGSTV protocol reverse-engineering lab (plan `0037`). There are
two separate execution paths. The current path is QEMU 8.2 + Ubuntu ARM64 +
Redroid 8.1. The old Android Emulator 28.0.25 path is retained only as
reproducible historical evidence of the TCG failure found there.

None of the current runners stores credentials or reads `.env`. The preparation
runner and the disposable `boot` scenario do **not** attach, install, or run an
APK. The separate `boot-benign` scenario accepts only the pinned harmless probe
described below; it cannot accept MAGSTV or an arbitrary APK. Neither path uses
ADB.

## Current path — QEMU 8.2 + Ubuntu ARM64 + Redroid

`redroid-lab-runner.sh` manages the prepared lab at
`/home/cdmonio/apk-work/arm64-redroid-lab`. `MAGSTV_REDROID_LAB` overrides that
location. Advanced overrides also exist for the QEMU/qemu-img/AAVMF paths,
SSH user/port, and transient unit name; they are environment variables only
and never cause the runner to source an `.env` file. It uses:

- QEMU 8.2 with `-accel tcg,thread=single`, 4 vCPUs, and 10 GiB RAM;
- AAVMF plus the already prepared `setup.qcow2`;
- `-netdev user,restrict=on,ipv6=off` with only SSH forwarded to
  `127.0.0.1:2224`, and `romfile=` on the virtual NIC;
- a transient `systemd --user` service, with QEMU diagnostics in journald.

### Preparation-only safety gate

This runner is **only for preparing and validating the base**. It opens
`setup.qcow2` directly in mutable mode: it is neither an immutable sealed base
nor a disposable run. Consequently, this runner never authorizes APK
execution, even when the operator owns the account and APK.

It aborts immediately if any of these variables is present in its environment,
without printing its value:

```text
MAGSTV_APK
MAGSTV_ALLOW_APK_EXEC
MAGSTV_USERNAME
MAGSTV_PASSWORD
```

The prepared disk has now been stopped, checked, flattened without a backing
file, and sealed read-only at:

```text
/home/cdmonio/apk-work/arm64-redroid-lab/immutable/redroid-base.qcow2
sha256 71e90a67b0402d22376f3f7b654f3f29541c7a595a88d48fe8b4663e3bf43626
```

Its UEFI VARS template and seal manifest live in the same `0555` directory.
All three files are mode `0444`. `redroid-disposable-runner.sh` implements the
separate overlay and host-sandbox gate described below. APK execution still
requires the explicit, hash-pinned `boot-benign` scenario; the preparation
runner never authorizes it.

The preparation runner never attaches `seed.iso`, the Redroid transfer ISO, an
APK, or an `.env` file. It exposes no ADB port. Stale PID, monitor-socket, and
serial-log paths are renamed with a UTC timestamp; they are never deleted. An
exclusive `runner.lock` serializes `doctor`, `start`, `check`, and `stop`; the
lock is rejected if it is a symlink, has extra hard links, changes inode while
opening, belongs to another user, or is group/world writable.

```sh
scripts/magstv-lab/redroid-lab-runner.sh doctor
scripts/magstv-lab/redroid-lab-runner.sh start
scripts/magstv-lab/redroid-lab-runner.sh status
scripts/magstv-lab/redroid-lab-runner.sh check
scripts/magstv-lab/redroid-lab-runner.sh stop

# Follow QEMU diagnostics:
journalctl --user -u magstv-redroid-lab.service -f
```

`doctor` validates QEMU 8.2, the pinned hashes, firmware, keys, and QCOW2
metadata. Before invoking any `qemu-img` operation it compares the device and
inode of `setup.qcow2` against `/proc/*/fd`; it skips QCOW2 inspection whenever
any accessible process has that inode open, regardless of its executable or
PID file. The managed-QEMU identity is stricter: the executable and complete
ordered `argv` must exactly equal the command generated by `start`, with no
additional option. Thus a manually launched VM is reported as unmanaged and is
never adopted by `check` or `stop`.

SSH uses the pinned host key in the laboratory's `ssh_known_hosts`; an unknown
or changed guest identity is rejected.

`check` uses SSH, not ADB. It validates the ARM64 guest, Docker, BinderFS and
its three devices, the exact running Redroid container/image/config digest,
Android version and `sys.boot_completed=1` via `docker exec`. The entire SSH
operation has a 180-second host timeout. It also requires:

- exactly one Docker network, `redroid-isolated`, marked internal;
- no default route inside Redroid plus a bounded negative TCP probe; Docker's
  transient gateway metadata is recorded but is not treated as a routing
  invariant; the outer Ubuntu guest also has no default route;
- the `zz-magstv-lab.rc` bind mount to be read-only, with SHA-256
  `c6c28632167102d0234c604381dd9873f4f9ac82f1ad2824d8bdc6f493e0d563`
  both at its source and inside the container;
- `vm.mmap_rnd_compat_bits=15`, `kernel.randomize_va_space=2`, and
  `dalvik.vm.extra-opts=-Xnorelocate`;
- the final boot workarounds already applied to the prepared disk:

```text
/dev/vda16 /boot ext4 noauto,nofail 0 2
/dev/vda15 /boot/efi vfat noauto,nofail,umask=0077 0 1
serial-getty@ttyAMA0.service: masked
boot.mount, boot-efi.mount, systemd-networkd-wait-online, snapd*: masked
```

Under single-threaded TCG, udev/blkid may take more than the default 90 seconds
to create the partition nodes. The earlier 10-minute device-timeout workaround
was discarded after proving that it only postponed the same wait. The final
base marks the nonessential boot mounts `noauto,nofail`. The serial getty is
also masked because this lab sends the UART to a host log file rather than an
interactive terminal, and waiting for `ttyAMA0` added another 90-second delay.
Other nonessential background services are masked in the prepared image to
reduce TCG load (including udisks2, ModemManager, pollinate, apport, rsyslog,
ubuntu-fan, multipathd, fwupd-refresh, update-notifier, apt-daily, and man-db
families). `check` samples the critical masks rather than coupling itself to
every optional package, and requires Docker, containerd, BinderFS, and
`ssh.socket` to remain enabled.

### Disposable offline baseline

`redroid-disposable-runner.sh` never opens `setup.qcow2`. For every `boot` it
creates a fresh QCOW2 overlay with the sealed base as its relative read-only
backing plus a fresh writable copy of the UEFI VARS template. It then runs the
entire deterministic scenario synchronously inside bubblewrap:

- a new user, PID, IPC, UTS, cgroup, and network namespace;
- no inherited capabilities, host home, `.env`, KVM, TUN, or mutable lab disk;
- no IPv4 or IPv6 default route in the host sandbox or Ubuntu guest;
- QEMU user networking with `restrict=on`, IPv6 disabled at the slirp boundary,
  and SSH forwarded only to loopback **inside** that private namespace, so port
  2224 is not visible on the host;
- QEMU's own seccomp sandbox and single-threaded TCG;
- exact checks for the pinned Redroid image, BinderFS, Android 8.1/API 27,
  ARM64/ARM32 ABI list, ART compatibility settings, internal Docker network,
  no Android default route, and negative TCP probes at sandbox, Ubuntu guest,
  and Android levels;
- bounded SSH and Android boot waits, clean container/guest shutdown, a final
  overlay `qemu-img check`, and verification that the sealed base hash did not
  change.

No run is reused or automatically deleted. Its manifest, serial output,
properties, process list, logcat, dmesg, Docker inspect data, and disk check are
retained under the external lab's `runs/<UTC>-<random>/` directory.

Baseline run `20260726T025859Z-eafb9264` completed with `result=pass`. It
validated the guest and evidence collection, recorded no IPv4/IPv6 default
route, observed negative TCP probes and zero Redroid restarts, then reached the
kernel `reboot: Power down` marker with QEMU exit status zero. A non-zero
`docker stop` status is retained as diagnostic evidence; clean teardown requires
the accepted whole-guest poweroff request, QEMU disappearance, the kernel
power-down marker, and QEMU exit status zero.

```sh
scripts/magstv-lab/redroid-disposable-runner.sh doctor
scripts/magstv-lab/redroid-disposable-runner.sh boot
scripts/magstv-lab/redroid-disposable-runner.sh boot-benign \
  /home/cdmonio/apk-work/benign-probe-gate-final-20260725T232439Z/jellyrin-benign-probe.apk
scripts/magstv-lab/redroid-disposable-runner.sh boot-magstv-offline \
  /home/cdmonio/mgstv-base.apk
```

The same four environment-variable gates used by the preparation runner apply
to this baseline runner. Bubblewrap also clears the remaining host environment
before starting the sandbox.

### Harmless ARM64/JNI gate APK

`build-benign-probe-apk.sh` builds a source-auditable control APK offline from
`benign-probe/`. It declares no Android permissions and contains only one
`arm64-v8a` JNI library that returns and logs a constant. The output and its
ephemeral signing key must live outside Git.

```sh
scripts/magstv-lab/build-benign-probe-apk.sh /external/output/directory
```

The builder validates the package name, API 27 floor, absence of permissions,
single ABI, archive contents, signature, alignment, and resulting SHA-256.
The reviewed artifact accepted by `boot-benign` is exactly 12,769 bytes with
SHA-256
`1d0b01a9f6aedd91acfb0fbec65422f5677c339e8d162a9c5928c94fc88a7351`.
Any other input is rejected before the sandbox starts.

The host opens that artifact once and passes only the already validated file
descriptor to bubblewrap as a mode-`0400`, read-only file. The sandbox
revalidates its hash and size, checks egress before and after execution, copies
it through SSH as a tar stream, verifies the installed package/component and
ARM64 ABI, launches it once, and requires the expected JNI marker/library hash.
It records tri-state evidence when an observation is unavailable, retains the
overlay and logs, and powers the guest off cleanly even when a validation fails.
No credential or MAGSTV input is accepted by this scenario.

### Pinned MAGSTV offline observation

`boot-magstv-offline` accepts only the literal
`/home/cdmonio/mgstv-base.apk`, a regular single-link file owned by the current
user, with exact size `35,272,343` and SHA-256
`2b098adf19eab4ac0eaf11501ebf386561677b2c95cc1f0499811bb81a058bb5`.
It is passed by descriptor as a mode-`0400` read-only snapshot; `.env`,
credentials, and host paths are not passed to the sandbox.

After the clean baseline and egress gate pass, the scenario installs the APK
offline and independently validates `com.android.mgstv` version `4.34.5`
(`43405`), its installed `base.apk` hash, ARM64 ABI, and
`WelcomeActivity`. It launches that activity once and observes processes,
per-PID maps, services, sockets, bounded logcat, and tombstones for 180 seconds
after the launch command finishes. IJiami `libexec*` and `libranger-jni.so`
observations are compared with pinned hashes.

The runner never starts `GoMediaService` manually. If `WelcomeActivity`
starts the private `com.android.mgstv:gomediad` process naturally, the event is
recorded passively; observation alone is not classified as malicious behavior.
All absence claims use `yes`/`no`/`unknown`, and application failure is reported
separately from containment or evidence failure. This scenario is implemented
and the baseline gate has passed, but it remains gated behind a successful
harmless-APK run.

## What the historical runner guarantees

- **Isolation:** minimal read-only mounts (the user's home is *not* visible),
  `--unshare-net/pid/ipc/uts/cgroup` + `--die-with-parent`. No external route
  reaches the guest; QEMU/ADB/crash-service die with the sandbox (no orphans).
- **Reproducibility:** an explicit, sha-pinned profile (Emulator 28.0.25 +
  `ranchu-api27-fixed.dtb` + API 27 google_apis image). Verified: `boot 3` = 3/3
  to `sys.boot_completed=1`.
- **Evidence:** each run writes `manifest.txt` (versions, hashes, host+guest
  network-isolation proof, home listing), `runner.log`, `emulator.log`,
  `logcat.txt`, `properties.txt`, `tombstones.txt` under `runs/<ts>-…-bootN/`.

## The audio-HAL patch (why boot needs it)

On this image, `StreamOut::getPresentationPositionImpl` in
`/vendor/lib64/hw/android.hardware.audio@2.0-impl.so` SIGSEGVs under TCG, killing
the audio HAL; `audioserver` then aborts in a loop and `system_server` never
finishes, so `sys.boot_completed` never reaches `1`. `patch_audio_hal.py`
replaces that function's prologue with a 24-byte safe early-return
(`*frames=0; *timestamp={0,0}; return 0`). The runner pushes the patched library
into the disposable AVD copy at runtime via `-writable-system` — the base image
and the APK are never modified.

The patch **must** be built from the exact guest library it targets: the script
verifies the prologue bytes, and the runner refuses to proceed unless the guest
HAL's sha matches the patch base (`GUEST_HAL_SHA_EXPECT`).

## L3 — offline APK execution (`run-apk`, gated)

`run-apk` boots+patches, then installs the APK offline, launches it once without
credentials, and collects loader-focused artifacts (install/verify output,
`ps -A`, the app's `/proc/<pid>/maps`, logcat, tombstones, guest sockets) plus
containment evidence (guest external reachability before and after). The
disposable AVD is destroyed afterward.

It is **gated off by default**: without `MAGSTV_ALLOW_APK_EXEC=1` it boots,
patches, records `apk_executed: no (gated)`, and stops — nothing untrusted runs.
The network stays isolated the whole time; the run aborts if the guest can reach
outside before the install.

```sh
# harness only (no APK executed):
MAGSTV_APK=/path/to/com.android.mgstv.apk \
  scripts/magstv-lab/magstv-lab-runner.sh run-apk

# actually execute the APK in the isolated lab (opt-in):
MAGSTV_APK=/path/to/com.android.mgstv.apk MAGSTV_ALLOW_APK_EXEC=1 \
  scripts/magstv-lab/magstv-lab-runner.sh run-apk
```

## Known limitation — the historical emulator can't run the APK's native code

Empirically (plan `0037`, L3), the APK does **not** install or run on this
QEMU-TCG ARM64 setup. The install helper `DefaultContainerService`, plus
`omx@1.0-service` and the audio HAL, all SIGSEGV with the same non-canonical
`0xffffff8…` garbage-pointer signature — a **systemic code-generation bug in
that bundled, old QEMU**, not anything specific to MAGSTV. Changing `-cpu`
within Android Emulator 28.0.25 does not alter the result. This negative finding
does not apply to the separate QEMU 8.2 + Redroid path documented above, which
is the current experiment. Containment held throughout (no network egress).
